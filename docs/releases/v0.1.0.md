# v0.1.0: Is it down, or is it me?

Initial public release of Website Health for Home Assistant. See the integration
manifest for the minimum supported Home Assistant version.

## Included

- HACS custom-repository installation and UI configuration.
- One config entry per website with any number of page or JSON checks.
- Page checks that require both a success code and chosen text in the served HTML;
  JSON checks that require valid JSON and chosen top-level keys.
- An internet check that runs after a failure, so a home outage reads as
  "My internet is down" and never as the site being down.
- Status, Problem, per-check, response time, last checked and optional published
  build entities.
- In-sweep retries, a failed-sweeps threshold, an optional heartbeat ping, and a
  notification blueprint.

## Verified scope

Automated tests cover the check engine against local HTTP fixtures, the config and
options flows, entity states, heartbeat delivery, diagnostics redaction and the
read-only contract. See the repository's Actions checks for the tagged revision and
`AUDIT.md` for the validation boundary.

## Important limits

- Read-only: GET requests only, plus the optional heartbeat.
- No JavaScript rendering: single-page apps expose only their HTML shell.
- No logins, custom headers, POST checks or regex matching.
- Checks appear as page views in analytics; filter them by user agent.
